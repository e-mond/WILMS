# WILMS v1.4.3 Hotfix Report

**Branch:** `hotfix/v1.4.3-financial-workflow`  
**Type:** Stabilization / critical financial workflow hotfix  
**Previous:** v1.4.2

## Objective

Fix release-blocking production workflow regressions introduced by financial hardening (v1.4.0–v1.4.2) without weakening RBAC, maker-checker, idempotency enforcement, SQL aggregations, display IDs, or audit logging.

## Root causes

1. **Disbursement 422** — External loan `status` collapses `PENDING_APPROVAL` → `PENDING_DISBURSEMENT`, so the UI offered Disburse before approval. Backend requires internal `lifecycleStatus === PENDING_DISBURSEMENT`.
2. **Reconciliation 400** — Production requires `Idempotency-Key`; frontend money POSTs never sent it.
3. **Review group missing** — Review DTO had `groupId`/`groupName` but UI never rendered them; no `groupDisplayId`; Assign Group was a stub.
4. **Admin fee SMS gap** — `recordAdminFee` persisted only; no SMS/email/in-app/audit notification path.
5. **Raw errors** — Backend semantics (`Idempotency-Key…`, validation prefixes) leaked into toasts.

## Fixes implemented

| Area | Change |
|------|--------|
| Loan DTO | Additive `lifecycleStatus` on loan detail |
| Loan UI | Approve action, Disburse gated on lifecycle + admin fee, workflow stepper |
| Errors | `LOAN_NOT_READY_FOR_DISBURSEMENT` + domain-safe FE maps |
| Idempotency | `financialMutation()` + `apiClient` headers on all scoped money POSTs |
| Review | `groupDisplayId`, Group line (`GRP-… — Name`), Assign Group wired |
| Admin fee | Deduped SMS/email/in-app + audit after record |
| Network UX | Retry / Refresh / Return to Dashboard |
| Diagnostics | Console/CSP noise documented as non-app defects |
